# 파일럿 키우기 · 인생 한 판 (기획서 v2)

상태: **기획 단계. 코드는 아직 없다.** 구현은 별도 세션의 Codex CLI가 맡는다. 이 문서만 보고 만들 수 있도록 규칙, 수치, 화면, 저장 형식, 티켓을 모두 적었다.
기준 코드는 PR #1의 머리 커밋 `c6c9d2e`(방식 C: 16걸음 고리 보드, 1~6 룰렛, 계절, 월급 칸, 갈림길 A/B, 승급 칸, 추가 행동)이다. 그 문서(`docs/design.md`, `docs/ui-spec.md`, `docs/nalidagame-integration.md`)와 파일 이름을 그대로 가리킨다.
이 문서의 모든 수치는 **시작값**이다. 13절의 시뮬레이션 검사를 통과하도록 `data.ts`에서 조정하고, 조정한 값은 `docs/design.md`에 옮겨 적는다.

## 0. 한눈에

사용자 요청은 일곱 가지다. 지도가 너무 작다, 19세부터 70세까지 사는 인생 게임이면 좋겠다, 돈은 넉넉하고 쓸 곳이 많아야 한다, 화면은 하나이고 나머지는 팝업이다, 직업은 조건이 맞는 것 중에서 고른다, 승진과 좌천이 있다, 전문직 지도로 옮겨 가면 더 빨리 큰다. 이후 한 판 길이는 1시간까지 괜찮다는 답을 받아 내용의 양을 그에 맞췄다.

| 항목 | PR #1 (방식 C) | 이 기획 |
| --- | --- | --- |
| 한 판 | 이전 커리어 판 | 19~70세, 204계절, 목표 평균 50분(40~60분). 세 시기로 끊어 쉬어 갈 수 있다 |
| 지도 | 22칸 한 장 | 여섯 장 212칸. 한 화면에 지도 한 장이 다 보이고 환승으로 옮겨 간다 |
| 이동 | 룰렛 한 번, 갈 곳 평균 1.1곳 | 룰렛 두 개 중 하나 선택. 갈 곳 평균 2.2~3.4곳, 차량이 있으면 3.7~8.5곳 |
| 직업 | 단계 8개, 정해진 순서 | 직업 19종. 조건이 맞는 직업을 골라 입사하고 이직한다 |
| 승급 | 승급 칸에서 도전 | 승급 심사 칸 + 매년 인사평가(경고, 좌천, 해고) + 특진 사건 |
| 돈 | 초중반에 빚이 기본 | 대출 없이 완주가 기본. 집, 가족, 사업, 투자, 취미, 노후에 쓴다 |
| 사건 | 38개 | 120개(기존 38 + 신규 82) + 행운 카드 16장 |
| 끝 | 엔딩 11종, 목표 달성 시 조기 종료 | 엔딩 21종. 70세까지 살고, 55세부터 조기 은퇴를 고를 수 있다 |
| 화면 | 보드 + 카드 패널 | 2D 탑 뷰 보드 한 화면 + 팝업. 3D는 쓰지 않는다(11절) |

핵심 결정 여덟 가지.

1. **계절 단위를 유지하고 204계절을 산다.** 한 계절 약 14초, 한 판 약 50분. 35세와 55세에 중간 결산 팝업을 두어 세 번에 나눠 하기 쉽게 한다. 저장은 지금처럼 선택마다 자동이다.
2. **지도 여섯 장.** 새싹 마을, 도심, 산업 벨트, 전문가 특구, 항구 신도시, 바닷가 휴양지. 모두 7×9 격자 안에 들어가 한 화면에 다 보이므로 "아무것도 스크롤하지 않는다"는 규칙이 그대로 선다.
3. **룰렛 두 개를 돌려 하나를 고른다.** 갈림 칸과 환승, 차량 보정까지 더해 도착할 수 있는 칸을 보드에 모두 표시하고 그중 하나를 누른다. "돌린 뒤 갈 곳이 적다"는 문제를 규칙으로 푼다.
4. **직업은 고른다.** 취업 · 이직 칸, 출발 칸 통과, 스카우트 사건에서 조건이 맞는 직업 목록이 뜨고 하나를 고른다. 단계(`Stage`) 8개를 직업(`track`) 19개와 직급으로 바꾼다.
5. **매년 겨울 인사평가.** 성과가 낮거나 직급 유지 조건이 빠지면 경고, 두 번 연속이면 좌천, 맨 아래 직급이면 해고다. 특진 사건은 조건을 건너뛰지만 유지 조건을 못 채우면 다음 평가에서 경고를 받는다.
6. **돈은 넉넉하게, 쓸 곳은 많이.** 급여를 PR #1의 약 1.4배(직급이 오르면 최대 3배)로 올리고 시작 자금을 60에서 500으로 올린다. 은행은 휴대폰 메뉴 안의 선택 기능으로 물러난다.
7. **행복 점수.** 집, 가족, 생활 수준, 여행이 행복을 올리고 최종 점수에 순자산과 함께 들어간다. 돈만 모으는 판과 삶을 꾸린 판이 둘 다 성립한다.
8. **목표 달성은 끝이 아니라 훈장이다.** 상장, 협회장 당선, 교육원 인가는 업적 점수와 칭호가 되고 인생은 70세까지 이어진다.

## 2. 인생 시간표

- 한 번의 이동이 한 계절이다. 19세 봄에 시작해 70세 봄에 끝난다. 51년 × 4계절 = **204계절**(`RULES.maxTurns = 204`, `RULES.startAge = 19`). 나이 = 19 + ⌊턴 ÷ 4⌋, 계절 = 턴 mod 4.
- 시기 세 개. 시기가 바뀌는 계절의 마감에 **중간 결산 팝업**이 뜬다(순자산, 직업과 직급, 가족, 집, 행복, 지금까지의 업적, 다음 시기 안내). 여기서 그만해도 저장은 남는다.

| 시기 | 나이 | 계절 수 | 예상 시간 | 주로 하는 일 |
| --- | --- | ---: | ---: | --- |
| 청년기 | 19~34세 | 64 | 약 16분 | 진학, 자격증, 첫 직업, 독립, 연애와 결혼 |
| 중년기 | 35~54세 | 80 | 약 20분 | 승진, 내 집, 자녀, 사업, 전문가 특구 |
| 장년기 | 55~69세 | 60 | 약 14분 | 정년, 자녀 독립, 노후 자금, 은퇴 생활, 물려줄 것 |

- 시간 모형(계절당 초). PR #1의 실측값(`SECONDS`)에 새 단계를 더했다.

| 단계 | 초 | 빈도(계절당) | 기여 |
| --- | ---: | ---: | ---: |
| 룰렛 두 개 돌림 | 1.5 | 1 | 1.5 |
| 도착 칸 고르기 | 3.0 | 0.9 | 2.7 |
| 이동 | 2.0 | 1 | 2.0 |
| 칸 팝업 선택 | 4.0 | 0.85 | 3.4 |
| 사건 응답(칸 사건) | 6.0 | 0.12 | 0.7 |
| 추가 행동 | 3.5 | 0.7 | 2.5 |
| 결과 읽기 | 2.4 | 0.35 | 0.8 |
| 인생 사건(2년에 한 번) | 6.0 | 0.125 | 0.75 |
| 큰 팝업(직업 선택, 집, 결혼, 환승, 연말) | 8.0 | 0.06 | 0.5 |
| 합계 | | | **약 14.9초** |

  204계절 × 14.9초 = 약 50.5분. 목표는 정책 평균 45~55분, 어떤 정책도 40분 아래나 60분 위로 나가지 않는 것이다.
- 조기 은퇴. 55세 이후 계절 시작 메뉴(휴대폰)에 "은퇴하고 여생을 보낸다"가 생긴다. 고르면 남은 계절을 건너뛰고 결산한다. 남은 계절마다 연금과 임대 · 상가 수입만 더하고 행복은 남은 해마다 +2다. 일찍 끝내도 손해가 크지 않게 하되 끝까지 일한 판보다 유리하지는 않게 한다.
- 나이와 체력. 체력 상한은 19~49세 100, 50~59세 90, 60~69세 80이다. 병 사건으로 더 내려갈 수 있다(상한 최저 60).
- 매년 겨울 마감에 **연말 정리**가 한 번 돈다: 인사평가(6.4절), 행복 정산(8.4절), 펀드 수익(8.6절), 집값 지수 변동(8.1절), 자녀 나이. 달라진 것이 있을 때만 팝업 한 장으로 보여 준다.
- 2년에 한 번(짝수 나이의 봄) **인생 사건** 하나를 지도와 상관없이 뽑는다(9절의 가족, 건강, 노년 사건 중 조건이 맞는 것). 칸 운과 무관하게 인생의 큰 일이 찾아오게 하기 위해서다.

## 3. 지도

### 3.1 여섯 장

모든 지도는 가로 7칸 × 세로 9칸 격자 위에 놓인다. 격자 한 칸은 360×740 화면에서 약 48px, 1366×768에서 약 70px이라 44px 누름 기준을 지킨다. 지도 한 장이 화면에 전부 보이고, 다른 지도로 갈 때는 화면이 전환된다. 이동은 한 방향(시계 방향)이다.

| 지도 | 칸 | 갈림 칸 | 모양 | 성격 | 급여 배수 | 생활비 배수 | 들어가는 조건 |
| --- | ---: | ---: | --- | --- | ---: | ---: | --- |
| A. 새싹 마을 | 33 | 2 | 바깥 고리 28 + 가로 지름길 5 | 시작 지도. 학교, 실습장, 시험장. 배움 칸이 많다 | 90% | 100% | 없음 |
| B. 도심 | 44 | 6 | 바깥 고리 28 + 안쪽 고리 12 + 연결 4 | 회사, 협회, 예식장, 병원, 부동산. 생활 칸과 취업 칸이 많다 | 110% | 130% | 없음 |
| C. 산업 벨트 | 39 | 5 | 바깥 고리 28 + 세로 길 7 + 가로 길 4 | 농경지, 건설 현장, 대교, 풍력, 해안. 일감 칸이 12개 | 100%, 비행 일감 130% | 90% | 없음 |

## 4. 이동 규칙

1. **돌린다.** 룰렛 두 개가 각각 1~6을 낸다(엔진이 시드 난수로 두 번 뽑는다).
2. **갈 곳이 표시된다.** 엔진이 `reachable(state)`로 도착 가능한 칸을 모두 계산한다.
   - 쓸 수 있는 걸음 수: 두 눈 각각. 차량 1등급(중고 경차)은 각 눈에서 1을 뺀 값도, 2등급(SUV) 이상은 1을 더한 값도 쓸 수 있다(최소 1걸음). 3등급(작업용 밴)은 1년에 한 번 "다시 돌리기"가 생긴다.
   - 걸음마다 `next`의 모든 갈래와, 환승 칸에서는 조건과 통행료를 치를 수 있는 다른 지도 갈래를 따라간다.
   - 결과는 `{ node, steps, path, fare, via }` 목록이다. 같은 칸에 여러 길이 있으면 통행료가 낮고 걸음이 짧은 길 하나만 남긴다.
3. **고른다.** 보드에서 표시된 칸을 누른다(`go:<칸 id>`). 갈 곳이 하나면 고르는 단계 없이 바로 간다.
4. **지나가며 생기는 일.** 월급날과 출발 칸을 지나면 장부를 정산한다. 출발 칸을 지나면 4.1절의 일이 더 생긴다. 승급 심사 칸을 지나는 길에 통과할 수 있는 심사가 있으면 PR #1처럼 그 칸에 멈춘다(도착 칸 표시에 "심사 정차"라고 미리 보여 준다).
5. **도착한다.** 칸 종류가 팝업을 정한다(5절). 그 뒤 추가 행동 하나, 계절 마감 순서는 PR #1과 같다.

`BoardState.step`은 `'spin' | 'pick' | 'space' | 'bonus'`가 된다. `'fork'` 단계와 갈림길 칸 종류는 없어진다. 갈림은 `next`가 둘 이상인 보통 칸이다.

### 4.1 출발 칸

지도마다 하나씩 있다. 지나가거나 멈추면 다음이 차례로 일어난다.

- 장부 정산(월급날과 같다).
- **한 바퀴 수당**: 그 지도의 출발 칸을 지난 지 8계절이 넘었으면 급여 한 계절분의 20%를 더 받는다(무직 · 학생은 30).
- **일자리 제안**: 학생(졸업 요건을 채운 경우)과 구직자에게 6.2절의 직업 선택 팝업이 뜬다. 이동이 끝난 뒤에 뜬다.
- 멈췄을 때의 칸 행동: 그 지도의 관공서 업무(이사 신고 = 거주지 옮기기, 8.1절).

### 6.2 직업을 고르는 순간

직업 선택 팝업이 뜨는 때.

1. 취업 · 이직 칸에 멈춘다.
2. 학생(8계절을 채움)이나 구직자가 출발 칸을 지난다.
3. 사건(헤드헌터, 특구 스카우트, 중년의 위기, 구조조정 뒤)이 연다.
4. 게임 시작 때 "바로 취업"을 고른다.

팝업의 규칙.

- 입사 조건을 모두 채운 직업 가운데, 지금 서 있는 지도가 그 직업의 심사 지도에 들어가는 것만 후보다("어디서나"는 늘 후보). 급여가 높은 순으로 최대 6개를 한 장에 3개씩 보여 준다.
- 조건 하나만 모자란 직업을 최대 2개 잠긴 카드로 덧붙이고 모자란 조건을 적는다(예: "이론 B가 필요합니다. 지금 C").
- 카드에는 직급 사다리, 첫 급여, 지금 지도의 배수를 곱한 실수령, 다음 직급 조건이 나온다.
- "지금은 고르지 않는다"가 늘 있다.
- 이직할 때 시작 직급은 0이다. 다만 새 직업의 1직급 조건(재직 제외)을 이미 채웠으면 1직급으로 들어간다(경력 인정). 헤드헌터 사건은 지금과 같은 번호의 직급까지 인정한다(그 직급의 능력치 조건을 채운 경우).
- 이직 뒤 4계절은 다시 이직할 수 없다(사건이 여는 경우는 예외). 그만두는 것("퇴사하고 구직자가 된다")은 취업 · 이직 칸과 승급 심사 칸에서 언제나 할 수 있다.
- 경영 · 조직 직군은 이 팝업이 아니라 PR #1처럼 해당 장소의 행동(등록, 설립, 출마)으로 시작한다. 팝업에는 "창업 안내" 카드로 조건만 보여 준다.

### 6.3 성과와 승급 심사

- 재직자는 **성과**(`perf`, 0~100)를 가진다. 입사와 직급 변동 때 50으로 맞춘다.
- 오르는 길: 일감 칸의 "근무" 성공 +8(실패 −4), 추가 행동으로 하는 직무 행동 +5, 대회 우승 +6, 사건. 내려가는 길: 근무를 4계절 연속 하지 않으면 계절마다 −3, 체력 탈진(20 미만)으로 계절을 마치면 −3, 사건.
- **승급 심사**: 다음 직급의 조건(능력치, 장비, 재직 계절)을 모두 채운 채 심사 지도의 승급 심사 칸을 지나면 그 칸에 멈춘다. 통과 확률은 50 + (성과 − 50)%로 30~95% 사이다. 통과하면 직급 +1과 승급 카드(PR #1의 카드), 떨어지면 성과 −10이고 4계절 뒤에 다시 볼 수 있다. 심사 비용은 없다.
- **전문가 특구의 가속**: 전문직 다섯 직업은 특구에 머무는 계절을 재직 2계절로 센다. 특구의 배움 칸은 능력치 상승 150%이고, 승급 심사 칸이 23칸 중 4칸이라 착지 비율이 17.6%(다른 지도 4.0~8.7%)다. 대신 생활비가 180%다.

### 6.4 인사평가, 좌천, 해고

매년 겨울 마감에 급여 직군(위 표에서 급여가 적힌 직업)을 평가한다.

| 결과 | 조건 | 효과 |
| --- | --- | --- |
| 우수 | 성과 80 이상 | 상여금 = 급여 한 계절분. 다음 심사 확률 +10%p(한 번) |
| 보통 | 그 밖 | 없음. 경고가 있었으면 지운다(성과 50 이상일 때) |
| 경고 | 성과 30 미만(공무원 20 미만), 또는 지금 직급의 **유지 조건**을 못 채움 | `warn` = 1. 팝업으로 무엇이 모자란지 알려 준다 |
| 좌천 | 경고 상태에서 다시 경고 사유 | 직급 −1, 성과 50, `warn` = 0. 좌천 카드(승급 카드의 반대 연출) |
| 해고 | 직급 0에서 좌천 사유 | 구직자가 되고 실업 급여 60을 4계절 받는다 |

- 유지 조건은 그 직급으로 올라올 때의 능력치 · 장비 조건이다(재직 계절 제외). 정식 심사로 올라왔다면 보통은 계속 채우고 있다. 빠지는 경우는 세 가지다: 추락으로 드론 등급을 잃었다, 평판이나 지지율이 사건으로 떨어졌다, **특진으로 조건 없이 올라왔다**.
- **특진**: "특별 승진", "낙하산 제안", 행운 카드 "발탁"은 조건을 보지 않고 직급을 +1 한다. 다음 인사평가까지 유지 조건을 채우지 못하면 경고, 그다음 해에도 못 채우면 좌천이다. 카드에 "유지 조건: ○○ 미달"을 미리 보여 주어 받을지 말지 판단하게 한다.
- **즉시 좌천**: "팀 사고 책임"의 해명 실패, 행운 카드 "한직 발령"(성과 −15) 같은 사건으로도 생긴다.
- 급여가 없는 직업(파일럿, 크리에이터, 레이서, 경영 · 조직)은 평가 대신 매년 직급을 조건으로 다시 계산한다. 조건이 빠지면 한 해의 유예 뒤 직급이 내려간다(같은 `warn` 값을 쓴다).

### 6.5 정년과 은퇴

- 급여 직군은 60세 봄에 **정년 팝업**이 뜬다. ① 은퇴: 퇴직금 = 급여 × 재직 총 계절 ÷ 8, 이후 연금 = 마지막 급여의 30%(공무원 50%). ② 촉탁 재고용: 급여 60%, 승급 없음, 65세까지. ③ 전향: 퇴직금을 받고 구직자가 되어 프리랜서 · 창업 · 가게 직원으로 다시 시작.
- 파일럿, 크리에이터, 경영 · 조직은 정년이 없다. 레이서는 45세에 은퇴하고 "코치 전향"(교관 1직급 입사 자격)을 얻는다.
- 은퇴 신분의 계절: 연금과 임대 · 상가 수입, 생활 · 여가 칸 중심. 일감 칸에서는 "재능 기부"(평판, 행복)와 "자문"(돈)을 할 수 있다.

### 6.6 지역과 직급에 따른 수입

실수령 급여 = 직급 급여 × 지도 급여 배수(3.1절) × 100분율 내림. 예: 드론 회사 과장 250은 도심에서 275, 신도시에서 325, 휴양지에서 200이다. 엔지니어 책임 연구원 390은 특구에서 585다. 비행 일감 보수는 산업 벨트에서 130%이고 파일럿 직급 배수와 곱한다(마스터가 산업 벨트에서 교량 점검 235를 하면 235 × 1.75 × 1.3 = 534).

## 7. 경제

### 7.1 원칙

- 단위는 만원, 정수. 급여와 생활비는 계절마다 장부에 쌓이고 월급날 · 출발 칸에서 정산된다(PR #1과 같다).
- **대출 없이 사는 것이 기본이다.** 필수 지출(생활비, 등록금, 자격증)은 어느 직업의 첫 급여로도 감당된다. 큰 지출(집, 사업, 결혼)은 모두 선택이고 싼 선택지가 있다.
- 은행은 휴대폰 메뉴에 남는다: 대출 100 · 500 · 2,000 단위, 계절 이자 1%, 신용 한도 = 1,000 + 급여 8계절분 + 보유 자산의 50%. 정산 때 모자란 돈이 자동으로 빚이 되는 규칙도 그대로다. 주택 담보 대출은 집값의 50%까지 집을 살 때 고를 수 있다.
- 빚이 신용 한도의 120%를 넘은 채 4계절이 지나면 **자산 정리**가 일어난다: 가게 → 펀드 → 두 번째 집 → 장비 순으로 70% 값에 팔아 갚는다. 판은 끝나지 않는다.

## 8. 생활

### 8.1 집

| 등급 | 집 | 값 | 계절 비용 | 휴식 칸 회복 | 계절 회복 | 연말 행복 | 살 수 있는 가족 |
| ---: | --- | ---: | ---: | ---: | ---: | ---: | --- |
| 0 | 본가(새싹 마을, 29세까지) / 숙소 | 0 | 0 / 20 | +60 | +20 | 0 | 혼자 |
| 1 | 월세 원룸 | 보증금 없음 | 25 | +60 | +20 | 0 | 혼자 |
| 2 | 전세 빌라 | 보증금 1,500(나갈 때 돌려받음) | 5 | +65 | +22 | +1 | 부부 |
| 3 | 소형 아파트 | 6,000 | 10 | +70 | +24 | +2 | 부부 + 자녀 1 |
| 4 | 중형 아파트 | 15,000 | 20 | +75 | +26 | +3 | 부부 + 자녀 3 |
| 5 | 대형 아파트 / 전원주택(휴양지 12,000) | 32,000 | 35 | +80 | +28 | +5 | 부부 + 자녀 3 |
| 6 | 펜트하우스(신도시) | 60,000 | 60 | +85 | +30 | +7 | 부부 + 자녀 3 |

- 집은 지도에 속한다(`home.map`). 회복 보너스와 "숙박비 없음"은 그 지도에 있을 때만 받는다. 연말 행복은 어디에 있든 받는다. 지도별 집값 배수: A 70%, B 100%, C 70%, E 130%, F 80%(특구에는 집이 없고 연구원 숙소만 있다).
- 부동산 칸에서 구하고, 사고, 판다. 이사 비용 80. 출발 칸에 멈추면 이사 신고로 같은 등급의 월세 · 전세를 그 지도로 옮길 수 있다.
- **집값 지수**(`homeIndex`, 60~200, 시작 100): 매년 겨울 −4~+6 사이에서 변한다(시드 난수, 평균 +1). 호황 · 침체 사건이 크게 움직인다. 살 때와 팔 때의 값 = 정가 × 지도 배수 × 지수 ÷ 100. 순자산에는 지금 지수로 친 값이 들어간다.
- 집을 두 채 이상 가지면 사는 집 말고는 세를 놓는다: 계절 수입 = 그 집 현재 값의 1.2%. 최대 4채.
- 결혼은 등급 2 이상, 자녀는 위 표의 인원까지. 가족이 늘었는데 집이 작으면 연말 행복 −3이다(강제 이사는 없다).

### 8.2 인연과 결혼

- `partner` 플래그는 소개팅(생활 칸의 문화 거리 · 수변 공원, 비용 30, 기본 45%, 평판 15마다 +1%p 최대 +20)과 사건으로 얻는다.
- 인연이 생긴 지 4계절이 지나면 예식장 거리(도심) · 리조트(휴양지)의 생활 칸이나 "프로포즈" 사건에서 결혼한다.

| 결혼식 | 비용 | 효과 |
| --- | ---: | --- |
| 작은 결혼식 | 300 | 행복 +20 |
| 예식장 | 1,200 | 행복 +35, 인맥 +10 |
| 호화 예식 | 3,500 | 행복 +50, 인맥 +20, 평판 +10 |

- 결혼하지 않아도 된다. 독신은 취미와 여행의 행복 효과가 150%다.

### 8.3 자녀

| 축의금 | 돈 −100, 인맥 +5 |
| 한 번 더 | 이번 계절에 한 번 더 돌린다 |
| 세 개의 룰렛 | 다음 이동에서 룰렛 세 개 중 하나를 고른다 |

| 발탁 | 급여 직군이면 특진 사건을 바로 연다. 아니면 평판 +8 |

## 10. 결산, 업적, 엔딩

70세 봄(또는 조기 은퇴)에 결산한다.

**최종 점수** = max(0, 순자산) + 행복 × 30 + min(30,000, 업적 점수)

### 11.4 훅과 검사

- PR #1의 `data-option`, `data-pick`, `data-nav`, `data-tab`, `data-action`, `data-screen`, `data-phase`를 유지한다. 새로 `data-dest="<칸 id>"`(도착 칸), `data-map="A..F"`(지금 지도), `data-popup="<이름>"`(위 스무 가지)을 더한다.
- `npm run layout:life`은 지도 여섯 장 × 네 크기와 팝업 스무 가지를 돈다. `check:board timed`는 16계절 대신 지도마다 12계절을 재서 14.9초 모형과 비교한다.
- UI는 지금처럼 `options(state)`를 그리고 `choose(state, id)`를 부를 뿐이다. 도착 칸 목록, 직업 후보, 집 값, 인사평가 결과는 모두 엔진이 계산해 준다.

## 12. 저장과 데이터 모델

### 12.1 상태(`GameState` v2)

```ts
type MapId = 'A' | 'B' | 'C' | 'D' | 'E' | 'F';
type SpaceKind = 'start' | 'pay' | 'train' | 'job' | 'contest' | 'event' | 'rest' | 'rankup'
  | 'jobfair' | 'shop' | 'estate' | 'life' | 'biz' | 'luck' | 'station' | 'invest';
type WorldNode = { id: string; map: MapId; kind: SpaceKind; place: PlaceId; x: number; y: number;
  next: string[]; cross?: { to: string; fare: number; gate?: Cond }[] };

type TrackId = 'service' | 'delivery' | 'mechanic' | 'clerk' | 'pilot' | 'employee' | 'instructor' | 'public'
  | 'rescue' | 'creator' | 'engineer' | 'inspector' | 'film' | 'atc' | 'racer' | 'solo' | 'company' | 'academy' | 'director';
type TrackDef = { id: TrackId; name: string; tier: 1 | 2 | 3 | 4; maps: MapId[] | 'any'; salaried: boolean;
  entry: Cond; entryRoll?: Roll; entryFee?: number; warnBelow: number; pensionPct: number;
  ranks: { title: string; salary: number; need: Cond; tenure: number; jobPct?: number }[] };

type GameState = {
  v: 2;
  seed: number; rng: number; turn: number;          // 0..204
  status: 'student' | 'jobless' | 'working' | 'retired';
  track: TrackId | null;
  phase: 'action' | 'event' | 'ended';
  board: {
    pos: string;                                     // 칸 id, 예: 'B-o7'
    step: 'spin' | 'pick' | 'space' | 'bonus';
    dice: [number, number] | [number, number, number] | [];
    ledger: Record<string, number>;
    lapAt: Record<MapId, number>;                    // 그 지도의 출발 칸을 마지막으로 지난 턴, 없으면 -1
    visited: number; laps: number;                   // 지도 여섯 개의 비트
    contests: number; rankups: number;
  };
  s: Record<Stat, number>;                           // 아래 추가 능력치 포함
  job: { rank: number; perf: number; tenure: number; total: number; warn: 0 | 1; changedAt: number; tracks: TrackId[] };
  home: { map: MapId; tier: number; deposit: number } | null;   // 사는 집
  estates: { map: MapId; tier: number; paid: number }[];        // 세 놓은 집, 최대 3
  holdings: { id: string; level: 1 | 2 | 3; paid: number }[];   // 가게, 최대 4
  family: { partnerAt: number | null; marriedAt: number | null; dual: boolean; kids: { born: number; pts: number; stage: 0 | 1 | 2 | 3 | 4 }[] };
  fund: { kind: 0 | 1 | 2; amount: number };
  life: 0 | 1 | 2 | 3;                               // 생활 수준
  timers: Record<string, number>;                    // 일시 효과가 끝나는 턴(차량 고장, 검진 효과 등)
  flags: string[];                                   // licensed, examiner, member, tech, degree, master, invite, ...
  feats: string[];                                   // 달성한 업적 id
  eventId: string | null; seen: Record<string, number>;
  ending: EndingId | null; score: number; log: LogEntry[];
};
```

- 새 능력치(`Stat`에 추가): `happy`(0~999), `fans`(0~999), `homeIndex`(60~200), `capStamina`(60~100). `rank`, `overdue`는 `job`으로 옮기거나 뜻을 바꾼다(`overdue`는 한도 초과 계절 수로 유지).
- 엔진 규칙은 그대로다: 순수 함수, DOM · `Date` · `Math.random` · 실수 없음. 퍼센트 계산은 정수 곱 뒤 내림.
- 새 조회 함수: `reachable(state)`(도착 칸), `jobOffers(state)`(직업 후보와 잠긴 이유), `review(state)`(다음 인사평가 미리 보기), `estateOffers(state)`, `lifeSummary(state)`(중간 결산과 내 인생 탭). 모두 `career.ts`처럼 읽기 전용이다.

### 13.3 순서

1. 세계 그래프와 이동만으로 무작위 보행을 돌려 3.1 · 3.3절의 표를 재현한다(이 문서의 값은 같은 방식으로 계산했다).
2. 직업과 경제를 넣고 `clerk_family`, `service_frugal`, `pilot`, `engineer` 네 정책으로 자산 · 은행 기준을 먼저 맞춘다.
3. 생활(집, 가족, 가게, 펀드)과 사건을 넣고 지출 · 행복 · 사건 기준을 맞춘다.
4. 16개 정책 전체로 엔딩과 점수 기준을 맞추고 `dominance`, `outcomes`를 통과시킨다.
5. 화면이 붙은 뒤 사람 속도 측정(`check:board timed`)으로 시간 모형을 고치고 2차 조정을 한다.

조정 손잡이의 우선순위: 급여 표 → 생활비 배수 → 집값 → 재직 조건 → 사건 가중치. 능력치 등급 경계(`GRADE_STEPS`)는 건드리지 않는다. 204계절이면 이전 커리어 판보다 능력치가 더 쌓이므로, S등급이 45세 이전에 흔하면 행동의 상승량을 일괄 85%로 낮춘다.

## 14. 구현 지침과 티켓

구현, 화면, 마감 단계는 이 문서를 쓴 쪽이 아니라 **별도 세션의 Codex CLI 구현자**가 맡는다. 그래서 이 절은 혼자 읽고 일할 수 있게 썼다: 14.1은 저장소 규칙(그대로 `AGENTS.md`에 옮긴다), 14.2는 v1과 v2를 나란히 두는 방법, 14.3은 티켓이다. 티켓 하나가 Codex 세션 하나다.

### 14.1 구현자 규칙 (`AGENTS.md`로 옮길 블록)

```md
# AGENTS.md — DroneGrowup (파일럿 키우기)

## What this is
Static browser game, Korean text, mobile first. Vite 5 + TypeScript strict, vanilla DOM + inline SVG.
No framework, no runtime dependencies (devDependencies only). Node 22+ runs .ts scripts and tests directly.
The default client is src/ui2; src/main.ts boots it without a query flag.
The v2 spec is docs/design/life-board.md. It is the source of truth for rules and numbers; do one ticket
from its section 14.3 per session and do not go beyond that ticket's scope.

## Git and PR rules
- Never merge a PR. Never push to main. Never force-push a shared branch. Never deploy.
- Work in your own worktree: `git worktree add ../.worktrees/dronegrowup-life-tNN -b feat/life-tNN-<slug> origin/main`.
  Do not edit files in another worktree or in the main checkout.
- One ticket = one branch = one PR against `main` (no other base; stacked PRs are not allowed).
  Start a ticket only when the tickets it depends on are merged into main. If told to bundle consecutive
  tickets, keep one commit per ticket in one PR.
- PR title: `life TNN: <ticket title>`. PR body: what changed, the acceptance checks with their output,
  anything you could not do. Do not include secrets or personal data.
- If a command is denied by a permission rule, stop that step and report the denial as it is.

## Engine rules (src/life)
- Pure functions only: no DOM, no Date, no Math.random, no floats in the state. Seeded RNG lives in the state.
- Money is an integer in 만원. A percentage is integer multiply then floor: Math.floor(x * pct / 100).
- Every number and every sentence lives in a data table (data.ts, world.ts, tracks.ts, life-data.ts, events-*.ts),
  not in engine code. The chance shown on a card is the chance that is rolled (clamped 5..95).
- Every event has one choice with no cost and no requirement. Every popup has a way out ("그냥 지나간다").
  A run can never get stuck.
- No choice of an event may be at least as good as another in every stat (npm run dominance:life).
- Every `need.min` on a graded stat is a GRADE_STEPS value.
- The UI renders what the engine returns (options, reachable, jobOffers, forecast) and calls choose(state, id).
  It never computes odds, pay, eligibility or endings.

## UI rules
- Nothing scrolls, on any screen at any size (390x844, 360x740, 1280x800, 1366x768). More content = tab or pager.
- Tap targets >= 44 px, text >= 11 px.
- Keep the hooks: data-option, data-pick, data-nav, data-tab, data-action, data-screen, data-phase,
  and the v2 hooks data-dest, data-map, data-popup.
- Strings from the server or from storage go into the DOM with textContent.
- Platform code stays inside `if (PLATFORM)`; the default build makes no network request.
- All names, text and art are original. Do not copy from other games.

## Before every PR
- `npm run verify` must pass (typecheck, build, tests and the v2 gates in package.json, including keyboard checks).
- `npm run simulate:life` enforces balance; include it in verify only when its full run takes at most 3 minutes.
  Otherwise run it separately before the PR. Do not weaken balance criteria.
- The platform client uses the new pilotgrowup-v2 leaderboard; NalidaGame server changes are a separate order.
- Also run the ticket's own commands listed in its "검증" line and paste their summary lines in the PR body.
- After changing a balance number: run the simulation and update the tables in docs/design.md.
- Tests: `tests/life-*.test.ts`, run by `npm test` (node --test). New rule = new test.
```

### 14.2 전환 전 병행 구현 기록

T23 이후 현재 구조: `src/main.ts`는 기본 URL과 `?life=1` 모두 `src/ui2/`를 실행한다.
