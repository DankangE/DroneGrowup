# 인게임 UI 방향 — 두 가지 안

결정 대기 중이다. 이 문서는 고르기 위한 요약이고, 어느 쪽도 아직 만들지 않았다.
계절 · 체력 개편(나이 · 계절 표시, 쉬기 버튼 두 상태, 계절 결산)은 두 안 모두에서 그대로 쓴다.
엔진(`src/game/`)은 화면을 모르므로 두 안 모두 규칙과 세이브는 건드리지 않는 것이 기본이다.

## A안 — 지도 → 건물 → 행동 → 화면 전환 → 실행

1. 화면: 지도가 홈이다. 건물을 누르면 그 건물의 행동 목록이 뜨고, 행동을 고르면 장소 화면으로 전환된 뒤 실행 장면(성공률 굴림 · 결과)이 그 화면에서 진행된다.
2. 지금과의 차이: 지금은 지도와 카드 패널이 한 화면에 같이 있다. A안은 "지도 화면"과 "장소 화면"을 나누고 그 사이에 전환 연출을 넣는다.
3. 이벤트: 계절이 바뀔 때 지도에서 해당 건물로 카메라가 이동한 뒤 이벤트 화면으로 전환하거나, 지도 위 팝업으로 띄운다. 가벼운 이벤트는 팝업, 진로가 갈리는 이벤트는 전환으로 나누는 것을 권한다.
4. 한 계절에 여러 번 행동하므로, 실행 뒤에는 지도로 돌아와 체력과 "이번 계절 행동 N회"를 보여 주고 다음 건물을 고르게 한다. 쉬기는 자취방 건물의 행동이다.
5. 엔진 영향: 없음. `options()`를 장소별로 묶어 보여 주는 지금 구조를 그대로 쓴다.
6. 필요한 그림: 장소별 배경은 이미 있다(등각 장면 18곳). 추가로 지도 위 건물 강조 상태, 전환 연출, 실행 장면용 소품(굴림 게이지 등) 정도.
7. 테스트: `data-*` 훅은 유지하되 화면 수가 늘어 레이아웃 검사 대상이 늘어난다.
8. 작업량: 중간. UI 3~4일(화면 분리 · 전환 · 이벤트 팝업), 그림 1일 이하. 위험은 "아무것도 스크롤되지 않는다" 규칙을 새 화면마다 다시 맞추는 일.

## B안 — 콘솔 인생 보드게임풍 (첨부 이미지의 느낌)

1. 참고 범위: 분위기와 장치만 참고한다. 그 게임의 이름, 캐릭터, 보드 배치, 그림, 문구는 쓰지 않는다. 모든 이름 · 글 · 그림은 새로 만든다.
2. 화면: 한 해가 네 칸(계절)인 보드 위를 말이 한 칸씩 나아간다. 칸에 도착하면 그 계절의 행동을 고르고, 계절이 끝나면 다음 칸으로 이동한다.
3. 승급 카드: 단계나 직급이 오를 때 전체 화면 카드가 뜬다. 캐릭터 그림, 직함과 별, 계절 수입과 증가분, 다음 직급, 능력치 등급, 다음 승급 조건을 보여 준다.
4. 능력치 등급: 체력 · 이론 · 조종 실력 등을 숫자 대신 글자 등급(예: G~S)으로 보여 준다. 숫자는 상세 화면에 남긴다.
5. 룰렛 연출: 지금의 성공률 굴림을 룰렛이나 다이얼이 도는 장면으로 보여 준다. 확률은 카드에 적힌 그대로다.
6. 엔진 영향: 작음. 등급 구간표와 "다음 직급 · 조건" 조회를 `data.ts`/`derived()`에 더한다. 규칙 · 세이브 · 점수는 그대로다. 칸마다 다른 효과가 있는 진짜 보드 규칙까지 넣으면 엔진 개편이 되므로 이번 범위에서는 뺀다.
7. 필요한 그림: 가장 많다. 꼬마 체형 주인공(단계 8종 × 표정 2~3종), 보드 타일과 말, 승급 카드 틀, 룰렛, 등급 글자 배지. 지금의 등각 장면은 칸 배경이나 카드 삽화로 다시 쓸 수 있다.
8. 작업량: 큼. UI 6~8일, 그림 3~4일. 위험은 그림 양과, 지금의 "타이쿤 창" 스킨을 대부분 다시 입혀야 한다는 점.

## 고르는 기준

- 빨리 고치고 싶다, 지금 그림을 살리고 싶다 → A안.
- 게임의 인상 자체를 바꾸고 싶다, 승급의 손맛이 중요하다 → B안.
- 절충: A안으로 화면 흐름을 바꾸면서 B안의 승급 카드와 능력치 등급만 먼저 가져올 수 있다(A안 작업량 + 2일 안팎).
